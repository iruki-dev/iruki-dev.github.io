**MuJoCo·PyBullet 같은 외부 물리엔진을 쓰지 않고 강체 동역학·충돌·접촉을 전부 직접 구현한
3D 물리·게임 엔진.** 렌더링부터 강화학습 환경까지 한 패키지에 담아 PyPI에 배포했다.

|---|---|

| **역할** | 개인 프로젝트 — 설계 · 구현 · 검증 · 배포 전담 |

## 배경

물리엔진 래퍼를 쓰면 접촉이 왜 떨리는지, 에너지가 왜 조용히 새는지는 끝까지 알 수 없다.
그래서 "동역학과 접촉은 항상 우리 코드가 푼다"를 먼저 제약으로 세우고 시작했다. 외부 엔진은
`validation/`에서 같은 장면의 수치를 대조하는 기준값으로만 쓴다.

## 구현

- **물리** — 강체 동역학(RNEA / CRBA / ABA), SAT·GJK/EPA 충돌 판정, PGS 접촉 솔버,
  Coulomb 마찰, 6종 조인트, heightfield 지형
- **렌더링** — 실시간 OpenGL PBR, 디퍼드 렌더러(SSAO·CSM·Bloom), 소프트웨어 레이트레이서
- **게임 레이어** — ECS, 스켈레탈 애니메이션·블렌드 트리, 오디오, 파티클, 씬 관리, 에디터
- **강화학습** — Gymnasium 환경, JAX JIT+vmap 배치 롤아웃, PPO·SHAC 학습
- **아키텍처** — 물리 코어는 렌더러를 import하지 않고, 둘은 `SceneSnapshot`이라는 순수 데이터
  계약으로만 이어진다. 공개 API는 6개 개념(`World`·`Body`·`Joint`·`Shape`·`Viewer`·`Recorder`)으로 제한

## 기술적 과제

### 백엔드 두 개를 하나의 코드로 유지

NumPy와 JAX 양쪽에서 동일하게 동작해야 한다는 요건 때문에 엔진 전체를 함수형으로 작성했다 —
in-place 변형 금지, 상태는 입력에서 출력으로 전달, 난수는 전역 상태 대신 명시적 키로 관리.
두 백엔드가 같은 입력에 같은 수를 내는지를 테스트로 고정해, 성능을 위해 JAX로 옮길 때
정확성이 함께 흔들리는 일을 막았다.

### 정확성을 눈으로 판단하지 않기

물리 코드는 그럴싸해 보이면서 틀린다. 그래서 보기와 무관한 게이트 네 종을 검증 기준으로
넣었다 — PyBullet 가속도 대조(50쌍, 최대 오차 2e-11), 무토크·무감쇠 조건의 에너지 보존(0.1%
이내), 단진자 주기의 해석해 대조(0.01% 이내), 백엔드 간 수치 일치. 물리 코드를 고칠 때마다
이 네 개를 통과해야 다음 단계로 넘어갔다.

## 성과

- **외부 물리엔진 의존 0** — 동역학·충돌·접촉 전부 자체 구현으로 PyBullet 대조 50/50 통과
- **성능** — JAX JIT+vmap으로 RL 롤아웃 처리량 약 2,000배. 핫루프(PGS·GJK/EPA·BVH)는 Rust로
  재작성하되 Python 폴백을 둬서 Rust 확장 없이도 전체 테스트 통과
- **추상화 검증** — 15줄 진입 예제와 예제 앱 3종(FPS 배틀로얄 프로토타입 포함)이 라이브러리
  내부를 수정하지 않고 동작. 응용을 만들려고 코어를 열어야 하면 추상화 실패로 간주했다
