**여러 언론 보도를 모아 묶고, AI가 종합해 쓰는 아침 조간.** 하루 한 번 쓰고 여러 번 읽는
추가 전용 글 저장소로 설계했다. 기술 설계서와 편집 원칙 문서를 먼저 쓰고, 그대로 구현한 모노레포다.

| | |
|---|---|
| **기간** | 2026.10 · 6 커밋 |
| **역할** | 개인 프로젝트 |
| **기술** | Python(워커) · Next.js(웹) · PostgreSQL · Claude Message Batches · bge-m3 임베딩 |
| **규모** | 파이썬 8,000줄 · TypeScript 4,300줄 · 테스트 103개 |
| **상태** | 구현 완료, 아직 공개 운영 전 |

## 원칙과 구현

| 원칙 | 구현 |
|---|---|
| 글은 추가만 된다 | DB 트리거로 수정·삭제를 막고, 정정은 새 글로 올려 원래 글에 연결 |
| 독자가 읽을 때는 AI를 부르지 않는다 | 웹은 조립된 조간을 읽기만 하고, 조립은 워커 한 곳에서 |
| 검증을 통과한 글만 싣는다 | 규칙 11개, 실패하면 한 번 다시 쓰고 또 실패하면 그 묶음은 건너뜀 |
| 출처는 2곳 이상 | 매체 2곳 미만이면 폐기. 글마다 모델·프롬프트 버전 기록 |
| 원문 문장을 베끼지 않는다 | 원문과 겹치는 어절 열 길이와 5-gram 비율로 검사 |
| AI는 필요한 곳에만 | 중복 제거·묶기·선정·숫자 검증은 알고리즘, 글쓰기에만 LLM |

## 파이프라인

수집(robots.txt 준수, 도메인당 1초 간격) → 정규화와 중복 제거(형태소 SimHash) → 임베딩으로 같은 사건 묶기
→ 선정(매체 2곳, 24시간) → 배치 생성(예산 80%에서 알림, 100%에서 중단) → 검증 → 게시 → 조간 조립 → 발송.
