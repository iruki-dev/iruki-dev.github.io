**브라우저에서 완결되는 웹 도구와 게임을 모은 이중 언어 정적 사이트.** 계정·추적·데이터베이스
없이 ctrlcat.dev에서 운영 중이다.

| | |
|---|---|
| **기간** | 2026.05 |
| **역할** | 개인 프로젝트 — 설계 · 구현 · 콘텐츠 작성 · 배포 |
| **기술** | Astro 4 · React 18 · TypeScript · Tailwind CSS |
| **규모** | 도구 5종 · 게임 3종 · 5,800줄 · EN/KO 10개 라우트 |
| **배포** | ctrlcat.dev · GitHub Pages + Actions(푸시 시 자동 배포) |

## 배경

유틸리티를 검색해 들어가면 광고와 쿠키 배너를 지나, 브라우저가 즉시 처리할 수 있는 일에 데이터를
서버로 보내게 된다. 같은 기능을 전부 클라이언트에서 처리하고 정적 배포로 서버 자체를 없애면
개인정보 문제와 운영 비용이 동시에 사라진다는 것이 출발점이었다.

## 구현

- **도구 5종** — JSON 포매터, Base64 인코더/디코더, 색상 변환기(HEX·RGB·HSL), 비밀번호 생성기,
  단어 수 세기
- **게임 3종** — 스네이크, 무패 AI 틱택토, 숫자 맞히기
- **콘텐츠 아키텍처** — 항목 하나 = 메타데이터 마크다운 1개 + React 컴포넌트 1개. Astro 컬렉션
  스키마가 빌드 시점에 검증하므로, 잘못된 분류나 누락된 필드는 깨진 페이지가 아니라 빌드 실패로
  드러난다
- **이중 언어** — 기본 영어는 `/tools/`, 한국어는 접두사 라우트 `/ko/tools/`. UI 문자열은 전부
  `t(lang)`로 통일해 하드코딩을 없애고, 본문은 언어별 문서 컬렉션으로 분리했다
- **성능** — Astro 정적 출력으로 기본 JS 0, 상호작용이 필요한 컴포넌트만 React 아일랜드로
  하이드레이션

## 설계 판단

### Tools와 Games를 구조적으로 분리

두 섹션은 저장소·빌드·배포만 공유하고 공통 컴포넌트, 상호 링크, 오가는 내비게이션을 두지 않았다.
테마도 분리했다(도구는 차분한 시안, 게임은 바이올렛).

이 분리를 습관이 아니라 규칙으로 문서화한 이유는 무너지는 방향이 예측 가능하기 때문이다. 공통
헤더 하나에서 시작해 공통 카드, "이런 것도 있어요" 영역으로 번지고, 조용하고 빨라야 하는 유틸리티가
포털이 된다. 업무 중에 JSON을 다듬는 사람에게 스네이크를 노출할 이유는 없다.

### 위젯에 문서를 함께 붙이기

각 항목에 개념 설명 문서를 함께 작성했다. Base64 페이지는 이 인코딩이 왜 생겼는지, 암호화가
아니라는 점, 끝의 `=` 기호의 의미를 설명한다. 문자열만 붙여넣으러 온 사용자에게도 읽을 가치가
있고, 검색 유입 측면에서도 도구 하나짜리 페이지보다 유리하다.

## 성과

- **8개 항목 전부 클라이언트 처리** — 입력 데이터가 외부로 전송되지 않는다. "데이터베이스 없음"이
  약속이 아니라 구조적 사실
- **운영 비용 0** — 완전 정적 배포, `main` 푸시 시 GitHub Actions가 빌드·배포
- **항목 추가 절차 표준화** — 스캐폴딩 명령으로 마크다운과 컴포넌트를 생성하도록 만들어, 새 도구
  추가 시 레이아웃·라우팅·컬렉션 설정을 건드릴 필요가 없다
