**브라우저에서만 복호화되는 제로 지식 일기장.** 데이터베이스를 통째로 확보해도 일기를 읽을 수
없도록 양자내성 하이브리드 암호화를 적용하고, 자격 증명을 잃는 현실적인 경우까지 설계에
포함했다.

## 배경

일기는 아무도 읽을 수 없다는 확신이 있어야 솔직하게 쓸 수 있다. 그래서 "서버를 신뢰한다"는
전제를 제거하는 것을 요구사항으로 잡았다. 모든 암호화는 브라우저에서 끝나고 Firestore에는
암호문만 올라간다. 서버 코드는 Cloud Functions 5개뿐이며 시드·개인키·평문을 일절 다루지 않는다.

## 구현

- **하이브리드 암호화** — 마스터 시드에서 X25519와 ML-KEM-768(NIST 양자내성 표준) 키 쌍을
  결정론적으로 유도. 두 방식이 모두 뚫려야 열린다. 오늘 쓴 글이 몇 년 뒤에도 DB에 남아 있는
  성격이라 선택했다
- **단일 감사 진입점** — 모든 암호 연산을 `lib/crypto/`의 배럴 파일 하나로 통과시키고, 이 모듈은
  네트워크·Firebase 코드를 import하지 않는다. 암호 관련 감사 범위가 1,045줄로 고정된다
- **동등한 두 자격** — 암호와 Shamir 백업 코드 어느 쪽으로도 복호화·암호 재설정·코드 재발급이
  모두 가능. 한쪽을 알아도 다른 쪽의 실제 값은 얻을 수 없다
- **접근 게이트** — TOTP는 암호학적 요인이 아니라 서버 검증 게이트로 구현. 시크릿은 보안 규칙에서
  클라이언트에 완전히 차단하고, 실패 5회당 잠금을 뒀다
- **테스트 분리** — 암호 모듈 단위 테스트(Vitest)와 Firestore 보안 규칙 테스트(로컬 에뮬레이터)를
  별도 구성으로 운영

## 기술적 과제

### 백업 코드 재발급을 실제로 무효화하기

Shamir로 시드를 직접 쪼개면 재발급이 의미를 갖지 못한다. 옛 코드가 수학적으로 여전히 같은
비밀을 복원해내기 때문에, 새 코드를 추가 발급하는 것에 불과해진다.

그래서 한 단계를 넣었다. 코드는 무작위 AES 래핑 키를 쪼개고, 그 키로 시드를 감싼 결과만
저장한다. 재발급 시 새 래핑 키로 시드를 다시 감싸 저장된 암호문을 교체하면, 옛 코드는 여전히
옛 래핑 키를 복원하지만 그 키로 열 암호문이 더는 존재하지 않는다. 시드와 기존 일기는 건드리지
않으므로 자격 증명만 교체되고 모든 일기가 그대로 읽힌다.

### OTP가 최후 복구 경로를 막지 않게 하기

OTP 게이트가 일기 읽기를 무조건 막으면, 휴대폰을 잃는 것만으로 "무슨 일이 있어도 살아 있어야
하는" 백업 코드 복구 경로까지 함께 막힌다.

백업 코드에는 별도 우회 경로를 뒀다. 복원한 래핑 키에서 HKDF로 계산한 일방향 증명값을 서버
저장값과 대조해 같은 접근 권한을 얻는다. 실제로 K개 코드를 모아야 나오는 값이고 암호 경로는
래핑 키를 전혀 건드리지 않으므로, 암호만 탈취한 공격자에게는 이 우회가 아무 도움이 되지 않는다.

## 성과

- **평문·시드·개인키가 네트워크 요청과 서버 코드 어디에도 등장하지 않는 구조 확립.** 서버 로직은
  접근 게이트 역할만 수행하고 복호화 로직을 포함하지 않는다
- **자격 증명 상실 시나리오를 설계에 포함** — 암호를 잊어도 백업 코드로, 코드를 잃어도 암호로
  복구되며, 재발급은 옛 자격을 실제로 무효화한다
- **한계를 문서에 명시** — 두 자격을 모두 잃으면 복구 불가(제로 지식의 실제 비용), 프라이빗 작성
  모드의 CSS 블러는 곁눈질 차단 용도이며 암호학적 보호가 아니라는 점을 화면과 문서에 적었다
