# 데일리 뉴스레터 루틴 운영 메모

매일 아침 자동으로 뉴스레터 한 편을 써서 `main`에 푸시하고, GitHub Actions가 iruki.dev에 배포합니다.

## 구성 요소

| 위치 | 역할 |
|---|---|
| [`.claude/newsletter/PROMPT.md`](PROMPT.md) | **루틴이 따르는 지시문 전체.** 톤·구성·사실확인 규칙을 바꾸려면 이 파일만 고치면 됩니다 |
| `content/newsletter/YYYY-MM-DD.md` | 발행된 레터 한 편 (= `/newsletter/YYYY-MM-DD`) |
| `content/pages/newsletter.json` | 목록 페이지 `/newsletter` |
| `config/collections.json` | `newsletter` 컬렉션 정의 |

## 루틴 등록

Claude Code web → **Routines** → 새 루틴:

- **Schedule**: `0 22 * * *` (UTC 기준. 한국 시각 매일 오전 7시)
- **Environment**: 이 저장소(`iruki-dev/iruki-dev.github.io`)가 붙은 환경
- **Session**: 매 실행마다 새 세션 (fresh session per fire)
- **Prompt**:

```
iruki.dev 저장소에서 오늘자 아침 뉴스레터를 발행하세요.

먼저 `.claude/newsletter/PROMPT.md`를 처음부터 끝까지 읽고, 거기 적힌 순서와 규칙을 그대로 따르세요.
그 문서가 이번 작업의 유일한 기준입니다. 문서에 없는 판단이 필요하면 보수적으로 — 확인되지 않은 내용은 쓰지 않는 쪽으로 — 결정하세요.
```

> 발행 시각을 옮기려면 cron의 시(hour)만 조정하세요. 한국 시각 = UTC + 9시간이므로, 오전 6시 발행은 `0 21 * * *`입니다.

## 운영 팁

- **톤이 마음에 안 들 때**: `PROMPT.md` 5장(문체)의 "쓰지 않는 것" 목록에 실제로 거슬렸던 표현을 추가하세요. 추상적인 지시("더 자연스럽게")보다 금지 표현을 늘리는 쪽이 훨씬 잘 먹힙니다.
- **분야 비중을 바꾸고 싶을 때**: 4장 ③의 "세 꼭지는 서로 다른 영역에서 하나씩" 규칙을 원하는 비중으로 고칩니다.
- **코너를 늘리거나 줄일 때**: 4장의 본문 순서 ①~⑥을 수정합니다. 순서 번호와 마크다운 제목(`## ...`)을 함께 맞춰 주세요.
- **레터가 안 올라온 날**: 루틴 실행 기록의 마지막 보고를 확인하세요. `PROMPT.md` 8장의 중단 조건에 걸리면 일부러 발행하지 않고 보고만 남깁니다.
- **초반 1~2주**는 아침에 결과물을 훑어보고, 어색했던 부분을 그때그때 `PROMPT.md`에 반영하는 것을 권합니다. 프롬프트는 한 번에 완성되지 않습니다.
